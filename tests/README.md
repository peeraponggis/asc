# tests — ชุดทดสอบที่รันด้วย Node ล้วน

ไม่มี dependency ไม่ต้อง `npm install` ไม่มี build step
เหมือนกับตัวโปรแกรมที่เป็นไฟล์ static ล้วน

```bash
node tests/copilot-match.mjs
node tests/copilot-survey.mjs
node tests/copilot-holdout.mjs
```

`exit 0` คือผ่าน · `exit 1` คือตก

---

## ทำไมมีสามชุดสำหรับเรื่องเดียวกัน

หัวใจของ ASC Copilot คือการจับคู่คำถามภาษาไทยกับหัวข้อ ซึ่งวัดผลตัวเองได้ง่ายเกินไป
ถ้าเขียนคำพ้องโดยดูชุดทดสอบเป็นตัวตั้ง ตัวเลขจะสวยโดยไม่ได้แปลว่าใช้งานจริงได้

สามชุดนี้จึงมีหน้าที่ต่างกัน และ **ตัวเลขที่เอาไปอ้างได้มีชุดเดียว**

| ไฟล์ | หน้าที่ | ผลล่าสุด | อ้างเป็นความแม่นได้ไหม |
|---|---|---|---|
| `copilot-match.mjs` | ชุดที่ใช้วัดค่าฐาน และเป็นตัวกันไม่ให้กับดักเดิมกลับมา | 15/15 | ❌ เขียนคำพ้องโดยดูชุดนี้ |
| `copilot-survey.mjs` | คำถามเรื่องเดียวกันแต่พูดคนละสำนวน | 27/28 | ❌ วัดครั้งแรกได้ 15/28 แล้วเติมคำพ้องตาม |
| `copilot-holdout.mjs` | เขียนหลังปรับคำพ้องเสร็จหมดแล้ว **ห้ามปรับคำพ้องตามชุดนี้** | **20/25 = 80 %** | ✅ **ตัวเลขนี้** |

ค่าฐานก่อนมี Copilot คือ `AscKB.search()` ตัวเดิม ซึ่งได้ **ถูก 1/15**
เพราะตัดคำด้วยช่องว่าง ซึ่งใช้กับภาษาไทยไม่ได้

### ข้อควรรู้เกี่ยวกับเลข 80 %

ชุด holdout รันครั้งแรกได้ **76 % และตอบผิด 2 ข้อ** สองข้อนั้นเป็นข้อบกพร่อง
เชิงโครงสร้าง ไม่ใช่คำพ้องขาด จึงแก้ที่ตัวตัดสิน ไม่ได้แก้ด้วยการเติมคำ
เลข 80 % หลังแก้จึงยัง **มองในแง่ดีอยู่เล็กน้อย** เพราะข้อบกพร่องถูกพบจากชุดนี้เอง

ตัวเลขจริงที่เชื่อได้ที่สุดคือบันทึกคำถามของผู้ใช้ ดูได้จากปุ่ม **สถิติ** ในแผง Copilot

## กติกาเดียวที่ห้ามละเมิด

ทั้งสามชุดยอมให้ **ตอบว่าไม่รู้** ได้ แต่ **ห้ามตอบผิด**
ผู้ใช้เชื่อคำตอบที่ผิด การเดาจึงแย่กว่าการบอกว่าไม่รู้

ทุกครั้งที่แก้ตาราง `TOPICS` ใน `docs/asc-copilot.js` ให้รันครบทั้งสามชุดก่อนเสมอ
เพราะการเติมคำพ้องหนึ่งคำอาจไปแย่งคำถามของหัวข้ออื่นโดยไม่มีอะไรเตือน
