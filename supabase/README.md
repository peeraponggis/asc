# ย้าย ASC ขึ้น Supabase — คู่มือติดตั้ง

เอกสารนี้พาไปทีละขั้นจนใช้งานร่วมกันได้จริง ใช้เวลาราว 30–45 นาที

**ระหว่างที่ยังทำไม่เสร็จ ระบบเดิมยังทำงานตามปกติทุกอย่าง**
โค้ดจะเข้าโหมดคลาวด์ก็ต่อเมื่อ `supabase-config.js` ถูกใส่ค่าแล้วเท่านั้น
จึงติดตั้งทีละขั้นได้โดยไม่ต้องหยุดใช้งาน

---

## สิ่งที่จะได้

| | ก่อน | หลัง |
|---|---|---|
| ที่เก็บข้อมูล | เบราว์เซอร์ของแต่ละเครื่อง | ฐานข้อมูลกลาง |
| การแชร์ | ทำไม่ได้ | เจ้าของเชิญคนอื่นเป็นผู้ชมหรือผู้ร่วมแก้ไข |
| รหัสผ่าน | แฮชในไฟล์ที่เปิดอ่านได้จากเว็บ | ตรวจที่เซิร์ฟเวอร์ ตั้งรหัสเองทางอีเมล |
| ล้างข้อมูลเบราว์เซอร์ | งานหายหมด | ไม่กระทบ |
| รูปภาพ | เบียดพื้นที่ 5 MB ของเบราว์เซอร์ | เก็บแยกใน Storage |

---

## ขั้นที่ 1 · สร้างโปรเจกต์บน Supabase

1. สมัครที่ https://supabase.com (แผนฟรีพอสำหรับเริ่มต้น — ฐานข้อมูล 500 MB, ไฟล์ 1 GB)
2. กด **New project**
   - Region เลือก **Southeast Asia (Singapore)** เพื่อให้เร็วที่สุดจากไทย
   - ตั้งรหัสผ่านฐานข้อมูลแล้ว**เก็บไว้ให้ดี**
3. รอสร้างเสร็จราว 2 นาที

---

## ขั้นที่ 2 · สร้างตารางและสิทธิ์

1. เปิดเมนู **SQL Editor** > **New query**
2. เปิดไฟล์ [`schema.sql`](schema.sql) คัดลอกทั้งไฟล์มาวาง แล้วกด **Run**
3. ต้องขึ้น `Success. No rows returned`

ไฟล์นี้รันซ้ำได้โดยไม่พัง ถ้าต้องแก้อะไรภายหลังก็รันใหม่ได้เลย

สิ่งที่ถูกสร้าง

| | |
|---|---|
| `profiles` | ชื่อที่แสดงและสิทธิ์ผู้ดูแลระบบ สร้างอัตโนมัติเมื่อมีบัญชีใหม่ |
| `projects` | โครงการ เก็บ db0–db3 รวมเป็น jsonb ก้อนเดียว |
| `project_members` | คนที่ถูกเชิญ พร้อมสิทธิ์ viewer / editor |
| `project_list` | มุมมองสำหรับหน้าแรก คำนวณ kWp และสถานะให้เสร็จฝั่งเซิร์ฟเวอร์ |
| bucket `project-images` | รูปหน้าปกของแต่ละโครงการ |

---

## ขั้นที่ 3 · ใส่ค่าเชื่อมต่อ

1. ไปที่ **Project Settings** > **API**
2. คัดลอกสองค่านี้มาใส่ใน `supabase-config.js` ที่รากของโปรเจกต์

```js
window.SUPABASE_URL      = 'https://xxxxxxxx.supabase.co';
window.SUPABASE_ANON_KEY = 'eyJhbGci....';
```

> **คีย์ anon ใส่ในโค้ดที่เปิดเผยได้** เพราะออกแบบมาอย่างนั้น
> ความปลอดภัยมาจาก Row Level Security ในฐานข้อมูล ไม่ใช่จากการซ่อนคีย์
>
> **ห้ามใส่คีย์ `service_role` เด็ดขาด** คีย์นั้นข้ามสิทธิ์ได้ทั้งหมด
> ถ้าหลุดขึ้นเว็บ ใครก็อ่านและลบข้อมูลของทุกคนได้

จากนั้นคัดลอกไฟล์เข้า `docs/` (สั่ง `sync-docs.cmd`) แล้ว push

---

## ขั้นที่ 4 · ตั้งค่าอีเมล

Supabase แถมบริการอีเมลมาให้ แต่จำกัดไว้ไม่กี่ฉบับต่อชั่วโมง ส่งให้ 41 คนไม่ผ่านแน่นอน

1. **Project Settings** > **Authentication** > **SMTP Settings**
2. เปิด *Enable Custom SMTP* แล้วกรอกของผู้ให้บริการที่ใช้
   (Resend, SendGrid, Brevo หรือ SMTP ของ Gmail ก็ได้)
3. ที่ **Authentication** > **URL Configuration** ตั้ง
   - **Site URL** : `https://peeraponggis.github.io/asc/`
   - **Redirect URLs** : เพิ่ม `https://peeraponggis.github.io/asc/index.html`

ข้อ 3 สำคัญ ถ้าไม่ตั้ง ลิงก์ตั้งรหัสผ่านในอีเมลจะพากลับมาไม่ถูกหน้า

---

## ขั้นที่ 5 · นำผู้ใช้เข้าระบบ

จาก `user.js` มี 41 บัญชี เป็นอีเมลอยู่แล้ว 38 บัญชี
อีก 3 บัญชี (`supet`, `lpee`, `pat`) ต้องกรอกอีเมลจริงให้ก่อน

```bash
cd supabase
npm install @supabase/supabase-js
```

ดูรายชื่อก่อน (ยังไม่ส่งอะไรออกไป และไม่ต้อง npm install ก็รันได้)

```bash
node invite-users.mjs --dry-run
```

เปิด `invite-users.mjs` เติมอีเมลของ 3 บัญชีที่ยังไม่มีในตัวแปร `MANUAL` แล้วส่งจริง

```bash
node invite-users.mjs
```

แต่ละคนจะได้อีเมลคำเชิญให้ตั้งรหัสผ่านของตัวเอง
สคริปต์เว้นระยะ 2.5 วินาทีต่อฉบับ ถ้ายังติด rate limit ให้เพิ่มค่า `DELAY` แล้วรันซ้ำ — คนที่ส่งไปแล้วจะถูกข้ามเอง

**ตั้งผู้ดูแลระบบ** — หลังบัญชีของคุณถูกสร้างแล้ว รันใน SQL Editor

```sql
update public.profiles set is_admin = true where email = 'อีเมลของคุณ';
```

## ขั้นที่ 6 · ย้ายโครงการเดิมขึ้นคลาวด์

ทำที่เครื่องที่มีข้อมูลอยู่ **ทุกเครื่อง** เพราะข้อมูลเดิมอยู่แยกกันในแต่ละเบราว์เซอร์

1. เข้าระบบด้วยรหัสใหม่
2. ไปที่ **Settings** จะเห็นการ์ด *ย้ายโครงการเดิมขึ้นคลาวด์* พร้อมรายชื่อที่พบ
3. กด **ส่งขึ้นคลาวด์ทั้งหมด**

การย้ายเป็นการ**คัดลอก** ของเดิมในเครื่องไม่ถูกลบ
ตรวจให้ครบก่อน แล้วค่อยกด *ลบโปรเจกต์ของฉันทั้งหมด* ทีหลัง

> กดซ้ำสองครั้งจะได้โครงการซ้ำ ให้กดครั้งเดียวต่อเครื่อง

---

## การใช้งานหลังติดตั้ง

**แชร์โครงการ** — กดไอคอนรูปคนบวกบนการ์ด เลือกอีเมลแล้วเลือกสิทธิ์

| สิทธิ์ | ทำได้ |
|---|---|
| ผู้ชม (viewer) | เปิดดูทุกเมนู ส่งออกไฟล์และรูปได้ แต่แก้ไม่ได้ |
| ผู้ร่วมแก้ไข (editor) | แก้และบันทึกได้ แต่ลบโครงการและเชิญคนอื่นไม่ได้ |
| เจ้าของ | ทำได้ทุกอย่าง รวมถึงลบและจัดการคนที่ถูกเชิญ |

คนที่จะถูกเชิญได้ ต้องเคยเข้าสู่ระบบมาแล้วอย่างน้อยหนึ่งครั้ง (ระบบต้องมีโปรไฟล์ของเขาก่อน)

ผู้ที่เปิดโครงการในสิทธิ์ผู้ชมจะเห็นแถบสีเหลืองบอกไว้ตลอด และการแก้ไขจะไม่ถูกบันทึก

---

## ข้อจำกัดที่ต้องรู้

- **ต้องออนไลน์** ตามที่ตกลงกันไว้ ไม่มีโหมดออฟไลน์ ถ้าเน็ตหลุดระหว่างทำงาน
  ข้อมูลบนหน้าจอยังอยู่ แต่การบันทึกจะขึ้นเตือนสีแดงพร้อมปุ่มลองใหม่ อย่าเพิ่งปิดหน้า
- **ไม่มีการล็อกเมื่อแก้พร้อมกัน** ถ้าสองคนแก้โครงการเดียวกันคนละหน้าต่าง คนที่บันทึกทีหลังจะทับของคนแรก
  ตกลงกันเองว่าใครแก้ตอนไหน
- **การบันทึกหน่วงไว้ 0.6 วินาที** เพื่อรวมคำสั่งที่ติดกัน ระบบจะส่งให้จบก่อนถ้ากดกลับหน้าแรก
  และจะเตือนถ้าปิดแท็บระหว่างบันทึก
- **ตารางจัดการผู้ใช้ในหน้า Settings ถูกซ่อนในโหมดคลาวด์** เพราะบัญชีย้ายไปจัดการที่ Supabase Dashboard แล้ว
- **ไฟล์สำรอง** ในโหมดคลาวด์จะดึงข้อมูลทีละโครงการ ถ้ามีเยอะจะใช้เวลาสักครู่

## ถ้าติดปัญหา

| อาการ | สาเหตุที่พบบ่อย |
|---|---|
| หน้าล็อกอินยังเป็นแบบเดิม (ช่อง "ชื่อผู้ใช้ / อีเมล") | ยังไม่ได้ใส่ค่าใน `supabase-config.js` หรือยังไม่ได้ sync เข้า `docs/` |
| "ติดต่อเซิร์ฟเวอร์ไม่ได้" | URL ผิด หรือตัวบล็อกโฆษณากันไลบรารีจาก CDN |
| "อีเมลหรือรหัสผ่านไม่ถูกต้อง" ทั้งที่แน่ใจว่าถูก | ยังไม่ได้กดลิงก์ตั้งรหัสผ่านจากอีเมลคำเชิญ |
| กดลิงก์ในอีเมลแล้วไม่เกิดอะไร | ยังไม่ได้ตั้ง Redirect URLs ในขั้นที่ 4 |
| "ไม่พบผู้ใช้อีเมลนี้ในระบบ" ตอนเชิญ | คนนั้นยังไม่เคยเข้าสู่ระบบ จึงยังไม่มีโปรไฟล์ |
| "ไม่มีสิทธิ์ทำรายการนี้" | สิทธิ์ที่ได้รับเป็นผู้ชม หรือพยายามลบโครงการที่ไม่ใช่ของตัวเอง |

เปิด Console ของเบราว์เซอร์ (F12) จะเห็นรายละเอียดเต็มของทุกข้อผิดพลาด

## ไฟล์ที่เกี่ยวข้อง

| ไฟล์ | หน้าที่ |
|---|---|
| `supabase/schema.sql` | โครงสร้างตาราง สิทธิ์ และที่เก็บรูป |
| `supabase/invite-users.mjs` | นำผู้ใช้เดิมเข้าระบบ รันบนเครื่องเท่านั้น |
| `supabase-config.js` | ค่าเชื่อมต่อ (แก้ไฟล์นี้ไฟล์เดียว) |
| `asc-cloud.js` | ชั้นเชื่อมต่อทั้งหมด หน้าอื่นเรียกผ่าน `window.AscCloud` |
| `index.html` · `master_shell.html` | สองไฟล์นี้เท่านั้นที่รู้จักคลาวด์ |

โปรแกรมออกแบบ รายงาน 3 มิติ และวางผังอุปกรณ์ **ไม่ถูกแก้เลย**
ทั้งสี่โปรแกรมยังคุยกับหน้าหลักด้วย postMessage เหมือนเดิม จึงไม่รู้ว่าที่เก็บข้อมูลเปลี่ยนไปแล้ว
