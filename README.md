# ASC — ProInventive Solar Suite

ระบบออกแบบโซลาร์เซลล์ครบวงจร ใช้งานผ่านเว็บ เก็บข้อมูลบน Supabase

เว็บจริง : https://peeraponggis.github.io/asc/

**สถานะงานปัจจุบันอยู่ใน [`STATUS.md`](STATUS.md)** — เปิดอ่านไฟล์นั้นก่อนเริ่มงานทุกครั้ง

---

## โครงสร้างโฟลเดอร์

| ที่อยู่ | งาน | หมายเหตุ |
|---|---|---|
| `docs/` | **เว็บทั้งหมด** — ทั้งต้นฉบับและสิ่งที่ GitHub Pages เผยแพร่ | แก้ที่นี่ที่เดียว |
| `supabase/` | **งานคลาวด์** — โครงสร้างฐานข้อมูล สิทธิ์ และสคริปต์นำผู้ใช้เข้าระบบ | |
| `capacitor/` | **แอปมือถือ Android** | ห่อไฟล์จาก `docs/` |
| `img/` | รูปต้นฉบับความละเอียดสูง | ที่เว็บใช้จริงอยู่ใน `docs/img/` |
| `bin/` | ไฟล์เก่าที่ไม่ใช้แล้ว เก็บสำรอง | |

## กฎเหล็ก

**แก้ไฟล์ใน `docs/` ที่เดียว**

เดิมไฟล์เว็บมีสองชุด (ราก กับ `docs/`) ต้องรัน `sync-docs.cmd` ทุกครั้งหลังแก้
ถ้าลืมแล้ว commit เว็บจริงจะเป็นของเก่าโดยไม่มีอะไรเตือน
ตอนนี้ยุบเหลือชุดเดียวใน `docs/` แล้ว ปัญหานี้จึงหมดไป และไม่มี `sync-docs.cmd` อีกต่อไป

**งานที่แตะไฟล์ชุดเดียวกัน ให้ทำในเซสชันเดียว**
ห้ามเปิดผู้ช่วย AI หลายหน้าต่างทำงานในโฟลเดอร์นี้พร้อมกัน เพราะทุกหน้าต่างแก้ไฟล์ชุดเดียวกันบนสาขา `main`
ถ้าต้องทำขนานจริง ให้แยก worktree (โฟลเดอร์คนละอัน สาขาคนละอัน)

## ไฟล์หลักของเว็บ

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | หน้าเข้าสู่ระบบ สมัครใช้งาน และหน้าแรกรวมโครงการ |
| `master_shell.html` | โครงหน้าหลัก เรียกโปรแกรมย่อยทั้งสี่ผ่าน postMessage |
| `asc_e_analysis.html` | วิเคราะห์โหลดไฟฟ้า |
| `asc_design.html` | ออกแบบระบบและถอด BOM |
| `asc_3d.html` | จำลอง 3 มิติ |
| `asc_report.html` | รายงานนำเสนอ |
| `device_location.html` | วางผังอุปกรณ์บนแผนที่ |
| `asc-cloud.js` | ชั้นเชื่อมต่อคลาวด์ทั้งหมด หน้าอื่นเรียกผ่าน `window.AscCloud` |
| `supabase-config.js` | ค่าเชื่อมต่อ Supabase (คีย์ anon เปิดเผยได้) |
| `user.js` | รายชื่อผู้ใช้เดิม 41 บัญชี ใช้เป็นต้นทางของรายชื่อที่อนุญาต |

โปรแกรมออกแบบ รายงาน 3 มิติ และวางผังอุปกรณ์ **ไม่รู้จักคลาวด์เลย**
ทั้งสี่ตัวคุยกับหน้าหลักด้วย postMessage เหมือนเดิม จึงไม่ต้องแก้เมื่อที่เก็บข้อมูลเปลี่ยน
